# PDF方針・Windows配布方針の仕様反映と影響確認

対象: `assessment_app_spec_v0.1.0.md`（本文バージョンを0.1.1-draftへ更新）。
参照先を維持するためファイル名は変更しない。アプリのバージョン0.1.0と仕様書の改訂番号は区別する。

## 今回の仕様変更

- 第1・2章: 最終利用者はWindows上でexeを起動し、Python等の開発環境・コマンド知識を必要としないことを追記。
- 第6章: 元PDFの不変性、assets配下のテンプレート・フォント管理、スナップショットからの再生成、将来の複数帳票対応を統合。
- 第7・8章: 長文を黙って切り捨てない方針、ブラウザ表示、A4・100%印刷、Phase 2は1枚目の氏名だけであることを明記。
- 第12章: 現Phase 2のPDF検証と将来の配布検証を分離。
- 第14章: 重複していた「配布・実行環境」を統合し、コンソール非表示、1フォルダ配布、リソースとユーザーデータの分離、更新時のデータ保持を明記。
- DBモデル、履歴保持、再アセスメントのINSERT、client_snapshotの保持仕様は変更していない。

## 現在の実装への影響

| 対象 | 現状 | 配布時の課題・変更案 |
|---|---|---|
| `app/db.py` | `__file__`からアプリ直下の`data/assessment.sqlite3`を決定 | 起動場所には依存しないが、配布物と同じ場所のデータはフォルダ差し替えで失うおそれがある。書込可能な永続データ保存先を別に定め、既存DBの保全・引継ぎを行う |
| `app/main.py` | `create_app(database_url=...)`でDB接続先を注入できる | 保存先変更のためにモデルを変更する必要はない。将来のランチャー等から適切な接続先を渡せる |
| `app/pdf/templates.py` | `Path(__file__).resolve().parents[2] / "assets"`を参照 | 特定のユーザー名やカレントディレクトリには依存しないが、開発時の配置階層を仮定している。配布リソースの基点を共通処理へ集約する案 |
| `app/pdf/fonts.py` | 同じ親階層計算で`assets/fonts/ipaexg.ttf`を参照 | PDFテンプレート側とパス計算が重複。共通のリソース参照処理に揃える案。フォント原本とライセンス文書を配布物へ含める |
| `app/views.py`・`app/main.py` | Jinja2テンプレートとCSSをPythonモジュール近傍から取得 | PDF資産だけでなくHTML・CSSの同梱位置も確認する必要がある。`__file__`方式そのものがexeで必ず失敗するわけではなく、採用する配布配置との整合確認が必要 |
| `pyproject.toml` | HTML・CSSはpackage-data指定あり。ルートの`assets/`は指定なし | 現在の開発実行では読めるが、この設定だけでPDF・フォントが配布物へ自動同梱されるわけではない。配布方式決定時に全リソースを明示的に含める |
| `app/pdf/renderer.py`・`app/routers/pdf.py` | PDFをメモリ上で生成しinline応答。元PDF・DBへ書かない | 今回の分離方針と整合する。ファイル保存機能を追加する場合に、ユーザーデータ側の保存先を使用する |
| 起動・終了 | 現在はREADMEのUvicornコマンドとCtrl+C | 最終利用者の「exeのみ・コンソール非表示・コマンド不要」は未実装。将来、内部サーバーの起動・終了とブラウザ起動を管理するランチャーが必要 |
| PDF履歴 | `Assessment.client_snapshot["name"]`を描画 | 方針に適合。現在のClient氏名へフォールバックしない。DB・履歴仕様の変更は不要 |

`output/pdf/assessment_name_sample.pdf` は検証用に生成したサンプルであり、アプリの通常保存先ではない。
`.venv313`、`.tools`、pytest用DBは開発・検証環境であり、最終利用者へ要求するものではない。

## 現Phase 2で必要なこと

1. 1枚目PDF・採用済みフォントをアプリ管理のassets配下から読み込み、元ファイルを変更せず氏名だけを重ねる。
2. 保存済みスナップショットの氏名を使用し、座標・文字枠・埋め込み・はみ出しを検証する。
3. PDF表示URLと保存済み画面からのリンクを用意し、HTTP応答と画像化したPDFを確認する。

上記は直前のPhase 2作業で実装済み。今回の将来配布方針によって、氏名PDF出力のために追加必須となるコード変更はない。
近い将来の改善案として、`app/paths.py`等にリソース参照を集約する。これは変更候補であり、今回ファイルは作成しない。
DBの現在の保存先は、既存データを保持するため今回変更しない。

- パッケージング方式・同梱レイアウトの選定とexe生成。
- Pythonや開発環境なしでの動作、フォント・PDF・HTML・CSSの同梱確認。
- コンソールを表示しない起動・利用・終了、サーバーの終了方法、既定ブラウザの自動起動。

- 将来のPDFファイル保存先。現段階ではブラウザへメモリ応答するため、新たな永続保存先は不要。
